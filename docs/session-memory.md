# 会话记忆与经验沉淀

## 回读

稳定架构、决策和经验文档能降低下一次 Design 的调查成本。具体读取顺序由目标项目决定，并应围绕当前任务收窄；最近会话日志不是通用入口，只在追溯未完成工作、人工验证或历史诊断时有价值。

## 沉淀

一次变更只有产生会影响后续工作的长期知识时才需要沉淀。系统边界、重大决定、重复验证的模式和跨环境证据分别进入目标项目指定的位置；插件不规定默认文档类型，也不为完成流程而制造记录。

## 三种记忆

- **会话日志**：一次工作的事实、证据和下一步，服务于短期接续。
- **决策记录**：长期有效的选择、上下文、取舍和后果。
- **经验文档**：多次验证的模式、工具使用方式和常见陷阱。

## 控制膨胀

- 重复引用的决定适合升级为稳定决策记录。
- 经多次验证的模式才适合成为可复用经验。
- 失败记录应保留因果机制和重新评估条件，而不是只留下结论。
- 已被稳定文档吸收的短期记录应按项目规则归档。

记录的目标是降低未来决策成本，而不是制造完整流水账。
